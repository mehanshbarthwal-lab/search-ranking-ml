Answered Away: Detecting and Costing Click-Suppression in Declining Content

Abstract

When a content page loses clicks, is it because fewer people see it, or because people see it just as often but stop clicking? This project builds a client-grouped classifier on FlyRank warehouse data to distinguish these two patterns using only prior-period signals that pass a decision-time leakage test. Logistic Regression reaches F1=0.350 (base rate 0.229) on a held-out, client-grouped split, corroborated by 5-fold cross-validation (mean F1=0.340, std=0.034). The resulting ranked action queue reaches precision@50=0.58, and is translated into a four-action editor playbook with an honest, lower-bound ad-equivalent dollar estimate of value at risk. Every extension tried after the initial result—new features, a stronger model, hyperparameter tuning, engagement data—converged on the same ~0.35 ceiling, treated here as a finding, not a shortfall.

Introduction / Problem Statement

A content team watching a page's traffic decline has one lever: refresh it. But "declining" hides two very different problems. A page can lose clicks because fewer people ever see it—normal visibility decay—or because roughly the same number of people see it and simply stop clicking, a pattern consistent with something answering the query before the click happens. Treating both as the same problem means editors sometimes refresh pages that were never losing visibility, and sometimes miss pages where a routine refresh was never going to help.

This project calls the second pattern answered_away—explicitly a behavioral label describing what the traffic data looks like, not a confirmed cause. No column in this dataset says what appeared on a search results page for any given query. The goal is a ranked queue that tells a content editor which pages to look at first, and which of two different fixes each one likely needs: a structural fix (a clearer direct-answer block near the top, FAQ-style content) for answered_away pages, or a routine refresh for pages that are simply losing visibility.

  • Unit of analysis: one content page (content_hash_id).
  • Decision this supports: which declining pages a content editor should fix, and with which kind of fix.
  • Cost of a wrong call: a structural fix on a page that only needed routine freshening wastes editor effort. Missing a real answered_away page and treating it as normal decay means it keeps losing clicks even after a refresh that was never going to touch the actual problem.

Data

Release: FlyRank ML Internship warehouse (Hugging Face), tables fact_content_daily_performance (partitioned by month) and dim_content.parquet, accessed via DuckDB over hf://.

Date windows: prior30 = February 2026, last30 = March 2026. All label and feature construction uses only prior30-period values, checked against a decision-time leakage test.

Scale: the March 2026 (last30) partition alone contains 9,841,378 rows (confirmed via a live row-count query in the executed capstone notebook).

Filtering: pages with gsc_impressions_prior30 >= 50 and gsc_clicks_prior30 >= 3, so percent-change labels aren't just noise from a tiny prior base. Pages with fewer than 60 days of history before the March 2026 decision date are excluded from the action queue entirely (1,268 pages on the Week 7 run).

What was excluded, and why: client_hash_id is used only for grouping the train/test split, never as a feature. content_age_days was scoped early but never actually added to the model's feature set—confirmed during validation as a documentation/code mismatch, not a leakage issue. AI-referral session columns were considered and dropped early, populated on only ~6% of pages in the starter sample—too sparse to support a classifier.

Public-safety: no client names, domains, raw queries, or URLs appear anywhere in this repo. All identifiers are pseudonymous hashes (content_hash_id, client_hash_id) used strictly for joins and grouping.

Methodology

Label definition (prior30 vs. last30, on the filtered base pool):

  • answered_away: impressions change ≥ -5% AND clicks change ≤ -15%
  • normal_decay: impressions change ≤ -15% AND clicks change ≤ -15%
  • stable_other: everything else

Leakage check: click_change_pct is not merely correlated with the label—it's an ingredient in the label formula, so it's excluded from the feature set entirely. Confirmed with a deliberate leakage experiment: an honest Random Forest scores F1=0.158 on a random split with no leak, versus F1=0.703 with click_change_pct added back in—that ~0.55 jump is the leakage signature the validation harness is built to catch.

Features: five prior-period numeric signals plus two categorical fields, none derived from the last30 window and none touching the label formula: gsc_impressions_prior30, gsc_clicks_prior30, gsc_avg_position_prior30, word_count, gsc_ctr_prior30, plus content_type and main_intent (one-hot encoded).

Baseline: a hand-written rule taken directly from the pattern_group thresholds. This comparison is circular by construction (F1=1.000, since the rule IS the label), and is reported honestly as such rather than presented as a valid baseline. The real reference point is an earlier honest, non-leaky Random Forest at F1=0.135 on a random split.

Model: Logistic Regression, chosen after Random Forest without class_weight='balanced' badly underperformed (F1=0.108) on this imbalanced, 22.9%-minority-class problem.

Validation design: GroupShuffleSplit grouped by client_hash_id (test_size=0.25, random_state=42), asserting zero client overlap between train and test. Corroborated with 5-fold GroupKFold (mean F1=0.340, std=0.034, range 0.296–0.378), confirming the single-split F1=0.350 is a fair representative estimate rather than a lucky split.

Interpretation: F1=0.350 is well above the 22.9% base rate, not just a reflection of it. Precision@50=0.58 is the decision-relevant number—of the top 50 pages the model ranks highest, 58% are true answered_away cases, which is what actually matters if an editor can only review about 50 pages a cycle.

Model ceiling: four separate extensions—content age/freshness features, XGBoost, hyperparameter tuning, GA4 engagement features—all converged on roughly 0.35 F1, none producing a meaningful lift. Treat this as evidence of a real ceiling on this feature set, not as a string of failed attempts.

Limitations & Honest Framing

What this work can claim: that a page's traffic pattern is consistent with click suppression (impressions steady, clicks falling); that this pattern is detectable above base rate using prior-period signals alone; a proxy dollar estimate of ad-equivalent value at risk, clearly labeled as an estimate.

What this work cannot claim: that AI Overviews, or any specific mechanism, caused a page's decline—no column in this dataset confirms what appeared on a results page for any query. It cannot claim measured revenue loss, since there's no conversion or order-value data, only ad-equivalent click value. It cannot claim causal proof of any kind—this is observational historical data with no controlled experiment behind it, association only.

Precision, not certainty: Precision@50=0.58 means roughly 4 in 10 of the top-ranked pages are not true answered_away cases. The playbook routes disagreements between the rule and the model to a review category rather than silently discarding them, but a human still has to look.

Client diversity: 59 total warehouse clients, only about 30 survive the volume filters, with extreme size imbalance (3 to 7,393 rows per client). The grouped-split F1 could shift on a warehouse with a different client mix—exactly why the split is grouped by client in the first place.

GA4 coverage: only about 31% of pages have GA4 engagement data; has_ga4_prior30 showed negative permutation importance, so engagement features were not pursued further as a lift lever.

Ranked Recommendations

The action playbook sorts test-set pages by the grouped-split Logistic Regression's predicted probability of answered_away (descending), then assigns one of four actions using both the model's confidence and the rule-based label as a cross-check:

  • structural_fix—top-ranked, rule-labeled answered_away, model confidence ≥0.3, no extreme swing. Add or improve a direct-answer block aimed at the query. 28 of the top 50 rows on the real run.
  • routine_refresh—rule-labeled normal_decay, no extreme swing. Standard content freshening.
  • verify_then_review—impressions or clicks moved more than 300% either direction. A swing that large is as likely to be a tracking artifact as a real behavioral shift, so it's checked before it's acted on. 4 of the top 50 rows.
  • investigate_quiet_risk—model confidence ≥0.6 but the rule did NOT label the page answered_away. The model seeing something the rule's thresholds miss is itself worth a human's attention. 18 of the top 50 rows—nearly as many as clean structural_fix cases.

Economics framing: ad-equivalent value at risk for the 28 structural_fix rows on this run totals $72.50—computed as (clicks lost) × cpc, an explicit proxy for what it would cost to rebuy that traffic via ads, not a measured revenue figure. Read as a lower bound: it only prices pages with nonzero cpc, so real value at risk across the full queue is understated by this figure alone.

Models/algorithms

  • Mathematical setting: Logistic Regression, binary classification (answered_away vs. not), class_weight='balanced', max_iter=1000, features standardized via StandardScaler before fitting. (Yes)
  • Assumptions: label is defined from prior30→last30 percentage change in impressions/clicks, not from any ground-truth cause; client_hash_id is used only for split grouping, never as a feature. (Yes)
  • Complexity: not applicable at this scale. Dataset is tens of thousands of rows after filtering, and Logistic Regression training is not the bottleneck. (N/A)

Theoretical claims

Not applicable—this is an applied/empirical paper, no theoretical proofs are made. (N/A)

  • Statistics: 9,841,378 rows pulled in the March 2026 / last30 partition alone. (Yes)
  • Train/test split: GroupShuffleSplit, grouped by client_hash_id, test_size=0.25, random_state=42, zero client overlap between train and test asserted. Corroborated with 5-fold GroupKFold. (Yes)
  • Exclusions: pages with fewer than 60 days of history before the March 2026 decision date are excluded. content_age_days scoped early but never added. AI-referral session columns dropped early due to sparsity (~6%). (Yes)
  • Dataset link: Gated access dataset, available to FlyRank ML Internship participants, see https://flyrank.ai. (hf://datasets/FlyRank/internship-warehouse). (Yes)
  • Data collection: not applicable—dataset provided by FlyRank, not collected by this project. (N/A)

Code

Experimental results

  • Hyperparameters: Logistic Regression used mostly with defaults plus class_weight='balanced'; tuning via 4-fold GroupKFold scored F1=0.349 (no meaningful change from 0.350). (Yes)
  • Number of runs: Single train/test split for the headline number (random_state=42), corroborated by 5-fold GroupKFold. (Yes)
