Answered Away: Detecting and Costing Click-Suppression in Declining Content

Mehansh Barthwal1
1FlyRank ML Internship Capstone · Machine Learning Track · 2026
Abstract. FlyRank's product currently flags declining pages using hand-written rules, including health scores, quick-win tags, and needs-attention flags. These heuristics work well in standard cases but break down when signals become numerous, tangled, or begin shifting. When a content page loses clicks, is it because fewer people see it, or because people see it just as often but stop clicking? This project builds a client-grouped classifier on an ~82 million row search performance dataset (1.17 GB) from FlyRank to distinguish these two patterns. Using only prior-period signals that pass a decision-time leakage test, we ask whether a learned model can outperform the fixed rule in exactly the gap where it struggles. Logistic Regression reaches F1=0.350 (base rate 0.229) on a held-out, client-grouped split, corroborated by 5-fold cross-validation (mean F1=0.340, std=0.034). The resulting ranked action queue reaches precision@50=0.58, and is translated into a four-action editor playbook with an honest, lower-bound ad-equivalent dollar estimate of value at risk. Every extension tried after the initial result (new features, a stronger model, hyperparameter tuning, engagement data) converged on the same ~0.35 ceiling. This consistency is treated here as a finding rather than a shortfall.

1 Introduction / Problem Statement

FlyRank currently flags declining pages in production using a hand-written system of fixed, human-chosen thresholds (such as health scores, quick-win tags, and needs-attention flags). While these rules operate successfully at scale, they fail when signals become numerous, tangled, or begin shifting in ways no static threshold anticipated. That gap is where this project sits: out of thousands of pages, which one should a human fix first, and can a learned model make that call better than the fixed rule does today? A content team watching a page's traffic decline has one primary lever: refresh it. But "declining" hides two fundamentally different problems. A page can lose clicks because fewer people ever see it, representing normal visibility decay. Alternatively, roughly the same number of people might see it but simply stop clicking. This second pattern is consistent with something answering the query before the click happens. Treating both as the same problem means editors sometimes refresh pages that were never losing visibility, and sometimes miss pages where a routine refresh was never going to help.

This project refers to the second pattern as answered_away. It is explicitly a behavioral label describing the shape of the traffic data, not a confirmed causal mechanism, as no column in this dataset identifies what appeared on a search results page for any given query. The goal is to produce a ranked queue that tells a content editor which pages to look at first and which of two different fixes each likely needs: a structural fix (like a clearer direct-answer block near the top, FAQ-style content) for answered_away pages, or a routine refresh for pages simply losing visibility.

Operating at the unit of a single content page (content_hash_id), this classifier supports the operational decision of allocating editorial effort. The cost of a wrong call is highly asymmetric: deploying a structural fix on a page that only needed routine freshening wastes valuable editor time. Worse, missing a real answered_away page and treating it as normal decay guarantees the page will continue losing clicks, even after a standard refresh that was never designed to address the actual problem.

2 Data

2.1 Source, Scale, and Time Windows

The underlying dataset is drawn from the FlyRank ML Internship warehouse via Hugging Face, utilizing the fact_content_daily_performance and dim_content.parquet tables, accessed natively via DuckDB over hf://. This project operates on a warehouse of roughly 81.8 million rows across a 1.17 GB search performance dataset. All label and feature construction relies strictly on the prior30 period (February 2026) to predict outcomes in the last30 period (March 2026). The scale of the active modeling partition is substantial: the March 2026 window alone contains 9,841,378 rows, confirmed via live row-count queries during model execution.

2.2 Filtering and Exclusions

To ensure percentage-change labels are robust rather than statistical noise from a tiny base, the pool is heavily filtered to pages with gsc_impressions_prior30 >= 50 and gsc_clicks_prior30 >= 3. Pages with fewer than 60 days of history before the March 2026 decision date are entirely excluded from the action queue (removing 1,268 pages on the final run). Features were scoped restrictively: client_hash_id is used strictly for split grouping and never as a predictive feature. Similarly, content_age_days was documented but deliberately excluded from the final model1, and AI-referral session columns were dropped early due to extreme sparsity2.

2.3 Public Safety Statement

No client names, domains, raw queries, or URLs appear anywhere in this repository or its outputs. All entity identifiers are pseudonymous hashes (content_hash_id, client_hash_id) used strictly for relational joins and grouped cross-validation.

3 Methodology

3.1 Label definition and Leakage prevention

The classification objective (prior30 vs. last30, on the filtered base pool) is defined logically:

  • answered_away: \Delta\text{impressions} \geq -5\% \;\land\; \Delta\text{clicks} \leq -15\%
  • normal_decay: \Delta\text{impressions} \leq -15\% \;\land\; \Delta\text{clicks} \leq -15\%
  • stable_other: everything else

Because click_change_pct is an ingredient in the label formula, it presents an extreme data-leakage risk if included as a feature. A deliberate leakage experiment confirmed this danger: an honest Random Forest without the leaky feature scores F1=0.158 on a random split, whereas reintroducing click_change_pct artificially inflates the score to F1=0.703. This ~0.55 jump acts as the leakage signature that the validation harness is built to proactively catch and block.

3.2 Feature engineering

The feature space was constrained to five prior-period numeric signals and two categorical fields, deliberately avoiding the last30 window and the label formula: gsc_impressions_prior30, gsc_clicks_prior30, gsc_avg_position_prior30, word_count, gsc_ctr_prior30, along with one-hot encoded representations of content_type and main_intent.

3.3 Baseline Circularity

The primary baseline is a hand-written rule derived directly from the pattern_group thresholds. Because the rule is the label, this comparison is circular by construction and yields a perfect F1=1.000. It is reported here not as a competitive model, but as a transparent intellectual boundary condition. The true modeling reference point is the early honest, non-leaky Random Forest scoring F1=0.135.

3.4 Model Selection and Validation

Logistic Regression was chosen as the primary architecture after a standard Random Forest (without class_weight='balanced') severely underperformed (F1=0.108) against the imbalanced 22.9% minority class. Validation relied on a strict GroupShuffleSplit grouped by client_hash_id (test_size=0.25, random_state=42) to assert zero client overlap between train and test. This single-split evaluation is corroborated by a 5-fold GroupKFold (mean F1=0.340, std=0.034, range 0.296–0.378), confirming the single-split F1=0.350 is a structurally sound estimate rather than an artifact of a lucky split3.

5 Limitations & Honest Framing

This work formally establishes that a page's traffic pattern is consistent with click suppression (steady impressions, falling clicks), and that this distinct pattern is detectable above base rate using exclusively prior-period signals. It provides a proxy dollar estimate of ad-equivalent value at risk, explicitly labeled as a lower-bound estimate.

What this work cannot claim: We make no claim that AI Overviews, or any specific search UI mechanism, caused a given page's decline. No column in this dataset confirms what appeared on a results page for any query.

Furthermore, we cannot claim measured revenue loss, as the dataset contains no conversion or order-value data, only ad-equivalent click value. This is observational historical data; any interpretation is associative, not a proof of causality.

Finally, we emphasize precision over absolute certainty. A Precision@50=0.58 means roughly 4 in 10 of the top-ranked pages are false positives. The playbook routes disagreements between the rule and the model to a review category rather than silently discarding them, but human oversight remains fundamentally necessary.

Client diversity: 59 total warehouse clients, only about 30 survive the volume filters, with extreme size imbalance (3 to 7,393 rows per client). The grouped-split F1 could shift on a warehouse with a different client mix.

GA4 coverage: only about 31% of pages have GA4 engagement data; has_ga4_prior30 showed negative permutation importance, so engagement features were not pursued further as a lift lever.

6 Ranked Recommendations

The action playbook sorts test-set pages by the grouped-split Logistic Regression's predicted probability of answered_away in descending order. It then assigns one of four actions using both the model's confidence and the rule-based label as a structural cross-check:

  • Structural Fix (28 of top 50 rows on the real run) Top-ranked, rule-labeled answered_away, model confidence ≥0.3, no extreme swing. Action: Add or improve a direct-answer block aimed at the query.
  • Investigate Quiet Risk (18 of top 50) Model confidence ≥0.6 but the rule did NOT label the page answered_away. Action: The model seeing something the rule's thresholds miss is itself worth a human's attention.
  • Verify Then Review (4 of top 50) Impressions or clicks moved more than 300% either direction. Action: A swing that large is likely a tracking artifact; investigate telemetry before acting.
  • Routine Refresh Rule-labeled normal_decay, no extreme swing. Action: Standard content freshening.

Economics framing: The ad-equivalent value at risk for the 28 structural_fix rows on this run totals $72.50, computed as (clicks lost) × cpc. This is an explicit proxy for what it would cost to rebuy that traffic via ads, not a measured revenue figure. It must be read as a lower bound: it only prices pages with nonzero cpc, so real value at risk across the full queue is understated by this figure alone.

  • Assumptions: label is defined from prior30 to last30 percentage change in impressions/clicks, not from any ground-truth cause; client_hash_id is used only for split grouping, never as a feature. (Yes)
  • Complexity: Not applicable at this scale. Dataset is tens of thousands of rows after filtering, and Logistic Regression training is not the bottleneck. (N/A)

Not applicable. This is an applied/empirical paper, no theoretical proofs are made. (N/A)

(Yes)
